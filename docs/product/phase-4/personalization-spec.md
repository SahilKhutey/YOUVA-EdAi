# YOUVA EdAI — Phase 4 Personalization Engine Specification

**Specification Version:** 1.0  
**Phase:** Phase 4 — Personalization Depth  
**Core Invariant:** More personalization is not automatically better personalization. Personalization sits strictly above the Phase 1 BKT engine and below Teacher Authority.

---

## 1. Recommendation Decision Pipeline (Cycle 5)

The personalization engine executes in a strict, deterministic sequence of 9 hierarchical layers. No lower layer may violate or supersede a higher layer:

```
[1. Safety Constraints]
       ↓ (Block unapproved content, check distress flags)
[2. Teacher Override & Historical Teacher Directives]
       ↓ (Teacher decision is unconditionally authoritative)
[3. Curriculum Prerequisite Validation]
       ↓ (Verify foundational concepts in Knowledge Graph)
[4. Current BKT Knowledge State]
       ↓ (P(L) mastery probability per concept)
[5. Spaced Repetition Review Schedule]
       ↓ (Prioritize items due for retrieval: 1d -> 3d -> 7d -> 14d)
[6. Learning-Pattern Signal (Cognitive Model v1)]
       ↓ (Response-time velocity, error recurrence, hint responsiveness)
[7. Deterministic Difficulty Selection]
       ↓ (EASY < 0.30, MEDIUM 0.30-0.70, HARD > 0.70)
[8. Candidate Recommendation Formulation]
       ↓ (Action: PRACTICE, REVIEW, RETEACH, ALTERNATE_EXPLANATION)
[9. Human-Readable Explanation Generation]
       ↓ (Persisted evidence payload for educator transparency)
[Surfaced to Teacher Dashboard & Student Learning Plan]
```

### Authority Hierarchy Invariant:
$$\mathbf{Teacher\ Override} > \mathbf{Personalization\ Recommendation} > \mathbf{Baseline\ Adaptive\ Rules}$$

## 2. Personalization Policy Versioning (Cycle 7)

Every recommendation generated by the engine must be bound to an immutable, versioned policy identifier. This ensures that months later, the system can answer: *"Why did the system make this recommendation?"*

```typescript
export interface PersonalizationPolicy {
  id: string;
  version: number; // Incrementing integer (1, 2, 3...)
  enabledSignals: string[]; // e.g. ["RESPONSE_TIME_PATTERN", "REPEATED_ERROR_RATE"]
  parameters: {
    minMasteryForAdvance: number;      // default: 0.85
    consecutiveCorrectRequired: number; // default: 3
    zpdTargetPCorrect: number;          // default: 0.60
    rapidGuessThresholdSeconds: number; // default: 4.0
    slowStruggleThresholdSeconds: number;// default: 90.0
  };
  createdAt: string;
  approvedAt: string | null;
  approvedBy: string | null; // Must be verified human SME / Product Lead
  status: "DRAFT" | "REVIEW" | "APPROVED" | "ACTIVE" | "RETIRED";
}
```

## 3. Baseline vs. Personalization Dual-Execution Engine (Cycle 9)

To prevent regression and allow empirical A/B evaluation, the system maintains two executable engines:

1. **BASELINE ENGINE (`PERSONALIZATION_ENABLED=false`):**
   - Pure Phase 1 Corbett & Anderson BKT.
   - Strict curriculum prerequisite order.
   - Deterministic difficulty selection.
   - Fixed spaced review schedule ($1d \to 3d \to 7d$).
2. **PERSONALIZED ENGINE (`PERSONALIZATION_ENABLED=true`):**
   - Baseline engine plus:
   - Empirical `LearningPattern` signals (rapid guessing vs. thoughtful struggle).
   - Validated concept DAG with misconception tagging.
   - Explainable personalized recommendations (`RETEACH`, `ALTERNATE_EXPLANATION`).

**Rollback Guarantee:** If any personalized heuristic degrades student mastery velocity or causes teacher friction, setting `PERSONALIZATION_ENABLED=false` immediately reverts the platform to the Phase 1–3 validated baseline without database corruption or downtime.
